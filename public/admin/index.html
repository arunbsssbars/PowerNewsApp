Data Playbook: Utilizing Firestore Collection & Power60 Algorithm

This operational playbook documents the exact mathematical formulation of our ranking algorithm, step-by-step procedures for fine-tuning custom LLMs using our Firestore collection, the complete scraping-to-Flutter pipeline, known system flaws, and our technical roadmap.

1

Current Pipeline Architecture: Scraper to Flutter

Detailed workflow of crawling, cleaning, discarding, summarization, and mobile rendering.

A. Crawling & RSS Aggregation (Every 20 Minutes)

A multi-source crawler queries 15+ verified Indian energy feeds (PIB Ministry of Power, Mercom India, PV Magazine, Financial Express Power, Economic Times Energy, LiveMint, CERC). Node.js uses axios with retry logic and custom User-Agent headers to pull both XML/RSS payloads and direct HTML articles.

B. Data Cleaning & Non-Power Sector Discarding

contentCleaner.js strips HTML tags, tracking pixels, promotional boilerplates, and ads. The PowerFilter checks whether the text matches core power sector taxonomies (generation, transmission, distribution, tariffs, DISCOMs). If an article is about general politics, celebrity news, or general finance, it is immediately discarded before touching the AI.

C. AI Summarization with 60-Word Constraint

Articles pass to Google Gemini 2.5 Flash. The system prompt instructs: "Write a factual, concise 60-word executive briefing for power engineers. Focus on MW capacity, investment (Rs. Cr), tariffs, and discom impact. Do not use bullet points or marketing fluff."

D. Strict Database Storage (Cloud Firestore)

Only summaries meeting strict criteria (length ≥ 75 chars, non-bullet narrative, not identical to title) are written to Cloud Firestore in ai_summaries with 14 indexed fields. If storage approaches 850 MB, our automated cron gracefully purges the oldest 30+ day records.

E. Dual-Layer Flutter Display (Offline SQLite + REST Sync)

The mobile app uses a dual-engine architecture:
1. Local SQLite (powernews_offline.db): Boots in 0ms with instant offline reading, category filters, and bookmarking.
2. REST API Sync (/api/news): Seamlessly pulls the freshest 7-day articles in the background and writes them into SQLite without blocking UI thread.

Step-by-Step: Creating the Power60 Custom Model

How to use our 1,277+ approved Firestore summaries to train an open-source model & eliminate API costs.

Step 1: Export Dataset (.jsonl)

Navigate to the ML Training tab and click "Download .jsonl Dataset". This exports all approved records with full original text as user input and the 60-word executive summary as model output.

Step 2: Fine-Tune an Open Model (Llama-3-8B or Mistral-7B)

Upload the power60_dataset.jsonl to Google Colab or Kaggle (free T4 GPU). Using Unsloth or HuggingFace PEFT (QLoRA), fine-tune for 3 epochs with a learning rate of 2e-4. The model learns our exact Indian power domain taxonomy, vocabulary, and 60-word concise structure.

Step 3: Quantize & Deploy for Zero Ongoing Cost

Convert the trained weights to GGUF format (Q4_K_M). Deploy on a private VPS or container via Ollama or vLLM. The server can then switch summarization from Gemini to the local Power60 engine, achieving $0 monthly API bills and total immunity from rate limits.

Current Flaws & The Way Ahead

Critical architectural bottlenecks and our concrete roadmap for improvements.

Current System Bottlenecks
  • Render Free-Tier Sleep: Node server sleeps after 15 mins of inactivity, leading to a 30-50s cold boot on first app open.
  • Gemini Quota Risk: Spikes in breaking news can exceed free rate limits (15 RPM), causing unsummarized delays.
  • Exact String Keyword Matching: Keyword system relies on substring matching rather than semantic embeddings, occasionally missing synonyms.
  • Wire Reprints: Same PTI/ANI story published on 4 different websites can produce duplicate cards if titles vary slightly.
The Way Ahead (Improvements)
  • Semantic Deduplication (Vectors): Embed headlines with lightweight embeddings and cluster by cosine similarity (>0.88) to group syndicated news into one master event card.
  • Self-Hosted Power60 LLM: Fine-tune and deploy custom 8B model to eliminate Gemini API costs and latency.
  • Async Job Queue (BullMQ / Redis): Decouple ingestion into background workers to keep web requests instantaneous.
  • FCM Push Notifications: Automatically push breaking CERC regulatory orders or major grid events directly to mobile users.

📐 PowerScore Mathematical Formula

Score = (Base + (KW × 50) + SrcWeight - ClumpPen) / (AgeInHours + 2)^1.5
  • Base (100 pts): Starting baseline for all verified news.
  • KW × 50: Each active keyword entity found in title/summary adds +50 points.
  • SrcWeight (+80 / -20): Reputable niche journals (e.g. PowerLine) receive +80; high-volume bulk feeds receive -20 to prevent saturation.
  • Solar Penalty (-30): Generic solar news penalized in default feed to allow transmission, SCADA, and OEM news to surface.
  • Anti-Clumping Rule: Solar/renewable stories are capped at a maximum of 2 consecutive cards; third is automatically swapped with next non-solar article.
